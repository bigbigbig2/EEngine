# Platform

Platform owns capability negotiation and validation/navigation tooling. It does not own renderer algorithms. Production capability negotiation remains in GraphicsContext.

## Current implementation summary

- Daily context reads domains/workstreams using the shared navigation module without acceptance artifacts. Design/execution roles come from workstream authority; paused workstreams are separate.
- Checks bind to registered runners; module checks run typecheck/build and explicitly named tests.
- verify --full runs the check set and suites. It does not schedule the matched browser cases; its GPU environment check runs only the probe.
- Case-local YAML, profiles and workloads project into the browser registry. The diagnostic runner checks identity, page freshness, errors, disposal and artifact ownership.
- GPU oracle has a separate real-browser harness, selected numerical oracles and a controlled wrong-kernel negative test.
- Claim promotion, evidence compaction and status commands are retired. The v3 diagnostic artifact rejects acceptance and records engine content identity; valid identity/error/dispose assertions are preserved.

## Known gaps and conclusion limits

doctor compares generated bytes without writing. docs verifier checks document structure and navigation, not prose truth. GPU oracles verify test-build input/output identity; browser diagnosis fingerprints conservative engine inputs. Catalog classifications and hashes do not prove algorithm correctness, quality or performance.

An environment probe proves device reachability; a mock or schema fixture proves its stated local assertions. Production correctness, quality and performance require their actual scenarios/oracles. Existing reports cannot promote an unrun scope.
