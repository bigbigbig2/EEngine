# Shading

Phase 1 deliberately had no production material or lighting resolve. The previous effect-owned sparse shading, AO, GI, reflection, shadow, and temporal passes were removed from the production Renderer. Phase 2 deleted `SurfaceFeature`, the old Sparse resolve/candidate/revision/publication owners and their private classifier. Shared Surface mathematics and live publication records now have independent owners. Phase 2 extracted reconstruction/material/PBR WGSL into `surface_material_kernel.ts`, defined logical Surface values plus separate program/publication identity in `render/surface/SurfaceProducts.ts`, and connected a per-class GPU ShadingWork producer/indirect Surface consumer. Browser diagnostics have compared textured PBR, nonzero direct light, mixed classes, geometric boundaries and one derived-tangent normal-map case against numerical references; authored tangent handedness, broader normal/lighting combinations and formal quality evidence remain open.

The target is explicit Surface reconstruction and material demand over the visibility hit, with valid full, coarse, reconstructed, or eventually reused results for every visible sample. Visibility decoding, interpolation, gradients, UV transforms, texture sampling and PBR mathematics are extracted into the new Surface kernel; the old owner is deleted. Temporal reuse waits for a valid identity and rejection contract.

The target decision is [ADR-0020](../adr/0020-clean-cut-renderer.md). The [historical implementation ledger](../porting/shading.md) is source material, not proof that the new shading owner exists. Current claim and case relationships are generated by `node tools/vibe.mjs context OEngine/src/render/pipeline/RendererCore.ts --claims --cases`.

## Current Production Path

The single Renderer frame now runs VisibilityKey/depth → optional pre-material spatial frequency plan → ShadingWork → per-class indirect Surface material evaluation → radiance Present. The plan admits static opaque unlit factor materials and publication-certified 1×1 unlit base textures to 2×2 or 4×4 evaluation; ordinary textured, lit and other visible samples remain full-rate. ShadingWork contains only the chosen representatives, and Present uses the same plan to reconstruct every covered sample from this frame. With neither class 0 nor class 2 active, the plan and its bindings are omitted; the explicit full-rate setting also prunes them on the same Renderer path. A class-2 scene can still have zero eligible blocks. No temporal reuse exists. The active PBR program uses geometry reconstruction, material evaluation and basic direct light; textured programs include explicit gradients and texture banks. Queue semantics and limits are in [ShadingWork V1](../specs/shading-work-v1.md), the conservative frequency conditions in [Frequency Plan V1](../specs/shading-frequency-plan-v1.md), and physical resource closure in [Surface Kernel Binding V1](../specs/surface-kernel-binding-v1.md). Diagnostic GPU readback shows reduced material-evaluation count and fail-visible identity errors; a same-scene GPU-timestamp comparison now exposes planning, queue, shading and Present costs. That diagnostic is not fixed-condition whole-frame performance evidence. Logical Surface values distinguish radiance, geometric normal, shading normal, motion, and material identity without assigning each a physical texture; the program key excludes Scene/material/texture publication generations, which belong to binding lifetime.

## Implementation Limits

SurfaceProducts currently declares semantic values and program/binding resource closure; it is not a complete cross-consumer Product Planner, and declaring normal or motion does not prove a production output. BoundedGpuWorkProtocol is allocation/control preflight, not proof of a complete shared GPU Work Runtime. The old shading.one-eval and shading.pipeline-pruning claims are retired; the new L1 shading.surface-structure declaration and [Surface/Work V1 contract](../contracts/surface-work-v1.md) describe the finite implemented scope without promoting runtime evidence. Formal evidence is not inherited from old cases.

Old-owner closure is complete in source. Wider lit/normal frequency research remains in Phase 4; shared Temporal begins in Phase 3. Full integration checks determine structural closure; runtime and performance require independent current-revision evidence.

## Owner Boundaries And Failure

Shading owns ShadingWork and Surface material evaluation; Visibility owns hit production; texture residency owns physical texture availability. No old sparse shading claim or browser evidence transfers to the new owner.

## Main Entrypoints And Proof

Primary entrypoints are `render/surface/SurfaceMaterialPass.ts`, `ShadingWorkPass.ts`, `SurfacePresentPass.ts`, `shaders/surface_material_kernel.ts` and `surface_material_program.ts`; RendererCore composes them. Root Render files have explicit domain routes; shading no longer owns a catch-all render/** path.
