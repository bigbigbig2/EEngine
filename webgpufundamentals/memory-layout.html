WGSL 结构体不是“紧挨着放”

同一个 struct Params、同一条 Pipeline、同一个三角形，只改变 JavaScript 写入 Uniform Buffer 的字节偏移。左侧故意把 vec3f 紧跟在 f32 后面；右侧遵守 vec3f 的 16 字节对齐要求。

错误：color 写在 byte 4 → Shader 读到 0 正确：color 写在 byte 16 → Shader 读到绿色

WGSL 声明

struct Params {
  scale: f32,   // offset 0
  color: vec3f, // offset 16
};              // size 32
f32 对齐
4 bytes
vec3f 对齐
16 bytes
color 偏移
16 bytes
结构体尺寸
32 bytes

vec3f 本身保存 12 字节，但起点必须是 16 的倍数；结构体总尺寸还要向最大对齐值 16 取整。因此“成员数据共 16 字节”不等于“Buffer 只需 16 字节”。

错误：按成员尺寸紧凑排列

JavaScript 把 color 写进 Float32 索引 1～3；Shader 却只会从索引 4～6 读取。

scalebyte 0 color.rbyte 4 color.gbyte 8 color.bbyte 12 Shader color.rbyte 16 = 0 Shader color.gbyte 20 = 0 Shader color.bbyte 24 = 0 尾部byte 28

正确：按 WGSL 对齐和偏移写入

Float32 索引 1～3 是填充；color 从索引 4，也就是 byte 16 开始。

scalebyte 0 paddingbyte 4 paddingbyte 8 paddingbyte 12 color.rbyte 16 color.gbyte 20 color.bbyte 24 尾部byte 28
